## 화면이 답해야 하는 것

**이 숫자가 아직 맞나, 그리고 얼마로 환산한 것인가.** 나머지 설계는 전부 이
질문에서 나왔다.

| 보여주는 것 | 어디서 |
| --- | --- |
| GPU 모델 | 어느 칩. H100, A100, B300 … |
| 수량 | 몇 장. **값과 따로** 둔다 — 한 칸에 "H100 x8" 로 적으면 옆의 머신 단가가 한 장 값으로 읽힌다 |
| 1장·1시간 | 장당 환산가. 머신 단가와 나란히 둔다 |
| 리전 | 그 값이 어느 리전 것인지. AWS 는 리전마다 다르다 |
| 출처 | 공급자 이름이 공개 요금 페이지로 걸린다 |
| GPU 메모리 | **한 장**의 메모리. 공개하지 않는 곳은 비운다 |
| 원가 | 공급자가 적어 둔 그대로. 통화도 그대로 |
| 환율 적용가 | 원가 × 그 옆에 적힌 환율. **저장하지 않는다** |
| 가져온 시각 | 마지막으로 "아직 이 값이 맞다"를 확인한 때 |
| 이 요금이 생긴 시각 | 이 값이 처음 나타난 때 |
| 환율과 고시 시각 | 환율 제공자가 말한 시각. 우리가 물어본 시각이 아니다 |
| 공급자별 수집 결과 | 다섯 곳 각각 답했는지, 못 했으면 왜 |

환산값은 **저장하지 않는다.** 공급자는 $3.85/GPU-hour 를 공개하지, ₩5,212 를
공개하지 않는다. 환산은 우리가 한 것이고 옆에 적힌 환율만큼만 믿을 수 있다.
그래서 환율은 스냅샷에 붙고, 행에는 공급자가 실제로 말한 값만 들어간다.

날짜가 둘인 이유도 같다. 3주째 그대로인 요금표도 현재 요금표다. "값이 안
바뀌었다"와 "아무도 안 봤다"는 다른 말이고, 한 칸으로는 구분이 안 된다.

## GPU 모델과 메모리

다섯 곳이 같은 것을 다 다르게 적는다. 그래서 세 칸으로 나눠 담는다 —
`gpu_model`, `gpu_count`, `gpu_memory_gb`.

| 공급자 | 모델 | 개수 | 메모리(한 장) |
| --- | --- | --- | --- |
| AWS | **안 준다.** 인스턴스 패밀리에서 유도 (`AWS_GPU_MODEL`) | `GPU` 열 | `GPU Memory`(머신 전체) ÷ 개수 |
| Nebius | 품목명 | — | 공개 안 함 |
| Kakao | `accelerator` "A100 x1" | 같은 칸 | 공개 안 함 |
| Naver | 표 **바로 앞 제목** "H100 (KVM기반)" | "1개 x 48GB" | 같은 칸 |
| VESSL | 품목명 | — | `VRAM` 열 |

**메모리는 한 장 기준이다.** AWS 만 머신 전체를 적으므로 개수로 나눈다. 한 행은
장당이고 다음 행은 머신당인 열은 비교가 안 되고, 비교가 이 화면의 전부다.

**모델명에서 메모리를 지어내지 않는다.** H100 은 어디서나 80GB 지만 A100 은
40/80, V100 은 16/32 로 나온다. 비는 칸은 "—" 로 둔다 — `Contact us` 를 0원으로
적지 않는 것과 같은 규칙이다. 현재 모델 77/77, 메모리 56/77.

`WARBOY` 는 GPU 가 아니라 FuriosaAI 의 NPU 다. Kakao 가 시간당 파는 실제
가속기라 이름은 적는다 — 값이 붙은 행이 이름 없이 비어 있으면 파서가 깨진
것처럼 읽힌다.

### 칩별 비교 — GPU 1장·1시간

화면의 세 번째 탭. 같은 칩을 파는 곳을 **GPU 1장·1시간 원화 단가**로 줄 세운다.

이 단위가 아니면 비교가 안 된다. AWS `p5.48xlarge` 는 H100 여덟 장이 한 줄이고
Nebius 는 한 장씩 판다. 머신 단가를 그대로 늘어놓으면 **포장 차이가 가격 차이로
보인다**. 그래서 `per_gpu_hour = 값 / gpu_count` 로 맞춘다.

| 공급자 | 고시 단위 | 환산 |
| --- | --- | --- |
| AWS | 머신 시간당 | ÷ `GPU` 개수 |
| Naver·Kakao | 머신 시간당 | ÷ 개수 |
| Nebius | **GPU-hour** | 그대로 (단위가 장당이라고 말한다) |
| VESSL | 시간당, 장당 | 그대로 (계산기가 「GPU 수량」을 별도 곱셈 인자로 둔다) |

개수를 모르거나 시간당 요금이 아니면 **비운다.** 1장이라고 가정하고 나누면
머신 가격을 장당 가격으로 공개하게 된다 — 이 칸이 막으려는 바로 그 잘못이다.
비교 불가 행은 정렬에서 맨 뒤로 보낸다(0 이 아니라 Infinity). 숫자가 없다고
1등이 되면 안 된다.

### 설명은 요금 이력이 아니다

`content_hash` 는 **값만** 본다. 공급자가 전에 비워 두던 모델명을 적기 시작한
것은 요금 변동이 아니고, 그것으로 히스토리가 차면 히스토리를 열 이유가 없어진다.
대신 "달라진 것 없음" 가지에서 설명 칸만 제자리 갱신한다(`_refresh_descriptions`).
이게 없으면 값이 안 변하는 한 모델명이 영원히 비어 있게 된다 — 0016 이 추가된
시점의 기존 행 전부가 정확히 그 상태였다.

## 리프레시 규칙

```
다시 가져오기
   │
   ├─ 값이 달라졌다  ──▶ 새 스냅샷. 이전 것은 그대로 남아 히스토리에서 열림
   │
   └─ 달라진 게 없다 ──▶ 스냅샷 그대로. refreshed_at 과 환율만 갱신
```

판정은 `content_hash` 하나로 한다 — 모든 행의 `(공급자, sku, 금액, 통화,
단위)` 를 정렬해 해시한 값. 정렬하는 이유는 공급자가 표 순서를 바꿨을 뿐인데
매번 "요금 변경"으로 읽히면 안 되기 때문이다.

지난 요금표를 열면 **그때의 환율로 계산된 환산값**이 나온다. 오늘 환율을
어제 가격에 적용하면 히스토리가 조용히 자기를 고쳐 쓰게 된다.

## 다섯 곳에서 어떻게 가져오나

다섯 중 **AWS 만** 기계가 읽으라고 만든 가격표를 낸다. 나머지 넷은 웹페이지고,
웹페이지는 개편된다. 그 사실이 이 모듈의 모양을 정했다.

| 공급자 | 출처 | 통화 | 방식 |
| --- | --- | --- | --- |
| AWS | `pricing.us-east-1.amazonaws.com` EC2 `index.csv` (202MB) + S3 `index.json` | USD | 행 단위 스트리밍 필터 |
| Nebius | `nebius.com/prices` | USD | div 그리드 (`pc-highlight-table-block__row`) |
| Kakao Cloud | `kakaocloud.com/pricing/calculator` 의 `__NEXT_DATA__` | KRW | JSON 요금표 |
| Naver Cloud | `ncloud.com/product/compute/gpuServer` | KRW | 서버렌더 `<table>` |
| VESSL.ai | `vessl.ai/pricing` | USD | `<table>` + 스토리지 카드 |
| 환율 | `open.er-api.com/v6/latest/USD` | — | 무인증 |

전부 리전은 서울(있는 곳은). 서울과 버지니아를 나란히 놓으면 다른 물건을
비교하는 것이 된다.

**AWS 202MB 를 버튼 누를 때마다 받지 않는다.** 파일 머리에 `Version` 이 있어서
앞 몇 KB 만 읽고 지난번과 같으면 나머지를 받지 않는다. 실측 2.0초 → 0.03초.

### 지키는 세 가지

1. **fetcher 는 예외를 밖으로 던지지 않는다.** 실패도 `SourceResult` 로
   돌아오고, 그 공급자의 직전 행들은 **그대로 유지된다**. 한 곳이 개편됐다고
   126행이 "삭제 126건"으로 기록되면 안 된다.
2. **아무것도 못 찾은 파서는 그렇다고 말한다.** 조용한 0 은 "이 회사가 GPU
   판매를 그만뒀다"와 똑같이 생겼다.
3. **공급자가 실제로 쓴 것만.** `Contact us`·`문의`·`-` 는 가격이 아니라
   건너뛴다(전화해야 하는 기계는 공짜 기계가 아니다). `Free` 는 가격이고 0 이다.

`ok / failed` 말고 **`reused`** 가 하나 더 있다. AWS 가 "판이 그대로"라고
답한 경우로, 성공이지만 행을 새로 주지는 않은 상태다. 이것을 `ok` 이면서
행이 0 인 것과 구분하지 않으면 AWS 가 전 기종을 단종한 것으로 기록된다.

### 네이버 스토리지는 없다

네이버는 스토리지 요금을 계산기가 나중에 그려 넣어서, 페이지에는 값 칸이
비어 있다. 빈 칸은 가격이 아니다. 읽었으면 **돈이 드는 스토리지에 0원을
공개**하게 되므로 읽지 않는다. 화면에는 네이버 스토리지가 0행으로 나오고,
수집 결과에 이유가 적힌다.

라우트는 전부 `require_super_admin_session`. GPU-hour 단가는 협상 카드라
회사 전체에 열지 않았다 — 읽기가 열려 있는 로드맵과 다른 점이다.

파서는 **실제 페이지에서 잘라낸 fixture** 로 시험한다. 라이브로 시험하면 남의
마케팅팀이 개편할 때 빨개지는데, 그건 정보이긴 해도 이 코드에 대한 정보가
아니고 새벽 3시에 할 수 있는 일이 없다. fixture 는 만들 때 **라이브 파싱
결과와 같은지 대조**해서 넣었다.

## 처음 켤 때

테이블이 없으면 화면이 503 과 함께 어느 마이그레이션인지 말한다.

```bash
.venv/bin/worklog ledger-migrate --apply
```

그 다음 화면에서 **다시 가져오기** 를 한 번 누르면 채워진다. 스냅샷이 아직
없으면 "아직 한 번도 가져오지 않았습니다"라고 적힌다 — 빈 표가 아니다.
